# Cup & Handle Scanner V1.0

Bybit USDT 무기한 선물의 **실제 15분봉**에서 컵앤핸들 후보를 찾는 모바일 웹 탐색기입니다. React 19 · TypeScript · Vite · TradingView Lightweight Charts 5. 자동매매·로그인·API 키는 없습니다.

## 실행

Node.js 24 및 npm 11 기준입니다.

```sh
npm ci
npm run dev
```

이 클라우드 환경처럼 홈 캐시 디렉터리에 쓰기 권한이 없으면 `npm ci --cache /workspace/.npm-cache`를 사용합니다.

개발 서버의 `/cup_and_handle/` 경로를 엽니다. 정적 프로덕션 검증:

```sh
npm test
npm run build
npm run preview
```

Chromium이 있는 Linux에서 브라우저 검사:

```sh
npm run dev
# 별도 터미널
npm run test:browser
```

`CHROMIUM_PATH`로 Chromium 경로, `APP_URL`로 실행 중인 서버 주소를 지정할 수 있습니다. 브라우저 테스트는 실제 Bybit 접근 결과를 먼저 기록한 뒤 테스트 프로세스에서만 합성 OHLCV를 가로채 카드·캔버스·필터·더 보기·차트 확대·오류 UI를 확인합니다. 테스트 데이터는 앱이나 공개 캐시에 포함되지 않습니다. 스크린샷/실제 브라우저 접근 결과는 `/tmp/cup-scanner-checks/`에 저장됩니다.

## 사용법

1. 최소 거래대금(기본 10M USDT), 단계, 최근 신호(3/5/10봉), 최소 점수(기본 60)를 선택합니다.
2. **검색 시작**으로 BTC/ETH를 제외한 모든 조건 충족 종목을 분석합니다. 기본 소스는 Bybit 직접 호출입니다.
3. 네트워크/CORS/지역 차단 시 오류를 확인하고 **Actions 캐시로 검색**을 선택합니다. 캐시는 자동으로 실시간 데이터인 것처럼 대체하지 않습니다.
4. 전체 대상의 분석 결과를 유지하되 카드는 5개씩 표시합니다. 단계·점수·최신 신호·거래대금 정렬 및 차트 확대/EMA 표시를 지원합니다.
5. 진행 중 **중지**하면 요청을 취소하고 정상 결과를 유지합니다. 새로고침은 현재 설정으로 다시 검색하며 같은 확정봉 구간의 캔들은 메모리 캐시를 재사용합니다.

품질 점수는 승률이 아닙니다. 수수료·슬리피지는 목표 계산에 포함하지 않습니다. 추격 위험 경고 기본값은 신호 진입가 대비 +2%입니다.

## 데이터 및 오류 정책

- `api.bybit.com/v5/market/instruments-info`: 페이지네이션, USDT quote/settle, Trading, LinearPerpetual만 선택합니다.
- `tickers`: 24H `turnover24h` 기준 필터. 개별 알트코인 예외 목록은 없습니다.
- `kline`: `category=linear&interval=15&limit=250`, 실제 OHLCV를 시간 오름차순으로 정리합니다. 요청 개수는 250이며 진행봉을 제외하면 보통 **249개 확정봉**이 남습니다. 신규 상장은 더 적을 수 있습니다.
- 중복 시각은 제거하되 서로 다른 값의 중복, 결측 간격, 잘못된 가격/거래량은 종목별 오류로 분리합니다. 37개 미만 확정봉은 분석 부족으로 기록합니다. EMA200은 200개 미만일 때 미산정으로 표시합니다.
- 동시 요청 4개, 타임아웃 15초. 403/429와 심각한 retCode는 새 요청과 진행 중 요청을 중지합니다. 나머지는 종목별로 기록합니다. 수집 실패를 패턴 0건과 구분합니다.
- 클라이언트 캔들 종료 여부는 Bybit 응답 서버 시각으로 판단합니다. 캐시 수집은 수집 시작 이전에 종료된 봉만 보관합니다. UI 시각은 KST입니다.
- 검색 도중 실시간 현재가는 **검색 시 받은 ticker 가격**이며 스트리밍 호가가 아닙니다. 캐시의 현재가는 수집 당시 가격입니다.

## 탐지 규칙과 비리페인팅

`src/lib/detector.ts`가 확정 OHLCV를 처리하며 `tests/`의 합성 자료는 검증 전용입니다.

- 피벗 고점은 좌우 각 3봉을 사용하고 오른쪽 3번째 봉이 종료되어야 확인됩니다. 평평한 동률 고점은 최초 점을 선택합니다.
- 컵 A~C는 30~100봉, 깊이 5~25%, 고점 차이 ≤3%, 회복률 ≥85%, 바닥 위치 25~75%, 하단 15% 체류 ≥3봉을 모두 요구합니다.
- 같은 오른쪽 림 C의 여러 A 후보는 **C 확인 시점에 알 수 있는 컵 점수**로 하나를 고릅니다. 패턴 ID는 종목 + A/C 시각입니다.
- C+3에 컵 확인 이력을 기록합니다. 그 이후 유효한 손잡이(3~15봉)를 확인하고 단계가 전이됩니다. 확인 전에 발생한 돌파는 소급해서 신호로 만들지 않습니다.
- 손잡이 저점은 컵 높이 상단 절반 및 조정 1/3 이하를 유지해야 합니다. 길이가 15봉을 넘으면 만료합니다.
- 돌파봉 **직전까지 확인된** 손잡이 피벗 고점이 2개 이상이면 최근 두 점의 추세선, 아니면 확정 C의 수평선을 사용합니다. 컵 상단 A 선과 별도로 표시합니다.
- 직전 종가가 돌파 문턱 이하였고 확정 종가가 현재 저항선의 100.1%를 넘으면 가격 돌파입니다. 거래량은 직전 20봉 평균의 1.5배 이상이 기준입니다. 부족해도 가격 돌파를 표시하되 거래량 점수가 줄어듭니다.
- 돌파 후 1~10봉에서 **돌파 당시 고정 저항값** ±0.3%에 접촉하고, 접촉 이후의 별도 확정봉 종가가 저항 위이면 리테스트 성공입니다. 돌파 후 손잡이 저점 아래 종가는 무효이며 리테스트 뒤에도 이 조건을 확인합니다.
- 최근 N봉은 마지막 확정봉을 포함하여 신호 나이가 0~N-1인 구간입니다. 무효·만료·기간 경과는 활성 카드에서 제외하고 별도로 집계합니다. 같은 종목의 활성 패턴 중 단계/점수 우선 1개를 카드로 표시합니다. 모든 종목과 후보는 분석합니다.
- 차트 A~D 마커는 **구조상의 위치**이며 신호 시점이 아닙니다. 신호는 E/R에만 표시합니다. 단계 이력은 각 단계가 실제 확인된 확정봉 시각입니다. 순차 prefix 재생 테스트로 미래 봉을 추가해도 과거 단계 이력이 바뀌지 않는지 검증합니다.

## 점수 (100점)

각 항목은 `src/lib/scoring.ts`의 별도 함수에 있으며 카드 상세에서 확인할 수 있습니다. `clamp(x)`는 0~1 제한입니다.

| 항목                   | 규칙                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| U자 10                 | `10 × clamp(바닥 체류 봉수 / (컵 기간 × 0.35))`; 짧은 V자 체류 감점       |
| 깊이 5                 | `5 × clamp(1 - abs(깊이% - 12) / 20)`                                     |
| 고점 일치 5            | `5 × clamp(1 - abs(A-C)/A/0.03)`                                          |
| 기간 대칭 5            | `5 × clamp(1 - abs(바닥 위치 비율 - 0.5) × 2)`                            |
| 손잡이 조정 10         | 컵 높이 대비 18% 조정을 중심으로 `10 × clamp(1-abs(조정비율-0.18)/(1/3))` |
| 상단 위치 5 / 길이 5   | 상단 절반 유지 / 3~15봉                                                   |
| 손잡이 거래량 10       | 컵 평균 대비 손잡이 평균 거래량 비율 r에 `10 × clamp((1-r)/0.5)`          |
| 돌파 거래량 10         | `10 × clamp(거래량 배수/1.5)`; 돌파 전 0                                  |
| 종가 돌파 10           | 확정 가격 돌파 시 10, 돌파 전 0                                           |
| 돌파 몸통·종가 위치 10 | 양봉 몸통/전체 범위와 (종가-저가)/전체 범위의 평균 ×10                    |
| EMA 15                 | EMA50>EMA200 10, EMA50이 3봉 전보다 높으면 5; 부족한 항목 0               |

EMA는 기간 SMA로 초기화한 지수평균, ATR14는 Wilder 방식입니다. 돌파 전에는 잠정 점수로 표시합니다. 점수는 후보에서는 최신 확인봉, 돌파에서는 돌파봉, 리테스트에서는 반등 확정봉 기준입니다. 리테스트가 확인되면 해당 신호 시점 기준으로 진입/ATR 손절도 재계산하며 이후에는 고정합니다.

손절은 D − ATR14×0.2, TP1은 진입+위험×2, 컵 목표는 돌파 저항+(A−B)입니다. 비양수 손절, 진입 이하가 아닌 손절, 진입 대비 0.01% 미만 또는 30% 초과 손절폭은 비정상으로 표시합니다.

## GitHub Pages 배포 및 캐시

1. 변경 사항을 `main`에 커밋·push합니다.
2. 저장소 **Settings → Pages → Source: GitHub Actions**를 선택합니다.
3. Actions의 **Collect market data**를 수동 실행합니다. 성공하면 실제 공개 OHLCV `market-cache` artifact를 생성하고 **Deploy Pages**가 빌드·배포합니다.
4. 배포 주소는 **Deploy Pages → github-pages environment** 또는 Settings → Pages에서 확인하세요. 이 문서는 확인하지 않은 공개 URL을 제시하지 않습니다.

`vite.config.ts` base는 `/cup_and_handle/`입니다. 앱은 루트 단일 화면이므로 하위 라우트가 없습니다. 실제 Pages 루트의 직접 접근·새로고침은 배포 후 확인해야 합니다. 로컬 프로덕션 루트 접근은 브라우저 검사로 확인할 수 있습니다.

수집 Actions는 매시 2/17/32/47분에 예약되어 있으나 GitHub 예약 실행은 지연되거나 저장소 비활성화 시 멈출 수 있습니다. 기본 최소 거래대금 10M이며 `MIN_TURNOVER`로 수집 하한을 바꿀 수 있습니다. 브라우저에서 캐시 하한 미만으로 검색하면 누락 가능성을 경고합니다. 캐시는 수집 시각/소스/부분 실패/오래된 상태를 표시합니다. 새 수집 전체 실패 시 이전 정상 artifact는 대체하지 않고 실패로 종료합니다. 배포 작업은 최근 성공 수집 artifact를 읽고, 없으면 직접 수집을 시도합니다. 수집이 불가능해도 앱은 배포할 수 있으나 캐시 없음 오류를 명확히 표시합니다.

**지역 제한:** GitHub 호스팅 runner도 Bybit가 차단하는 지역일 수 있습니다. 이 경우 Actions가 실패하며, Bybit 접근이 허용된 지역의 자체 runner로 수집 작업의 `runs-on`을 변경해야 합니다. 우회 프록시나 가짜 데이터는 제공하지 않습니다. 브라우저 직접 호출의 CORS 허용 여부 또한 실제 사용자 접속 지역/Bybit 정책에 따라 달라집니다.

## 현재 검증 범위

- 단위 테스트 및 로컬 프로덕션 빌드, Chromium 데스크톱/390px 모바일 기능 검증을 실행합니다.
- 실제 Bybit 수집은 개발 환경의 허용 도메인 정책에 의해 차단될 수 있습니다. 실패를 성공으로 간주하지 않습니다.
- 실제 GitHub Actions 실행, 공개 Pages URL, 배포 후 새로고침, 실데이터 차트/탐지 결과는 외부 접근과 배포 권한이 확보된 뒤 별도 확인해야 합니다.
- 탐지기는 명시된 구조 규칙 기반의 휴리스틱이며 시장 성과·승률 검증은 포함하지 않습니다. 250봉 창 밖의 패턴/손잡이 저점 이탈 이력은 추적하지 않습니다. 동일 창 내 이력은 매번 결정적으로 재생하며 영구 데이터베이스는 사용하지 않습니다.
